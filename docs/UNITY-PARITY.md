# Unity 网页版还原进度

目标是还原本仓库的网页版版本。规则以对应源码为基准，社区资料只作交叉核对，避免把官方新版差异混入旧版复刻。

## 资料与机制

- [原项目](https://github.com/sganggs/Stronghold-Protocol)：休整期调度中心、部署、装备，自动战斗，单人及合作。
- [PRTS 玩法帮助](https://prts.wiki/w/卫戍协议/帮助)：战前情报、策略轮选、休整、作战、联防和最终作战。查阅日期 2026-10-11。
- 三同名初始干员晋升精锐、奖励高阶招募机会；商店升级价格随回合变化。实际实现由 `PlayerState` 与 `Match` 负责。
- 对版本敏感的部署顺序、领袖与回合参数，采用当前源码数据，不能仅凭攻略印象改动。

## 本次接入

`tools/unity-match-session.mjs` 复用原 `Match` / `PlayerState` / `Battle`，不重新编写经济、晋升和结算。虚拟时钟每次 step 推进 100ms，单线程串行命令；localhost `/match` 与旧单场 `/command` 分离。输入通过原协议校验，规则引擎继续校验阶段、资金和位置。

Unity `-match` / `play-unity-match.cmd` 提供中文流程测试入口：确认情报、选择策略与机变、招募、刷新、冻结、升级、选择手牌部署、方向、撤回、出售、准备、暂停、托管、重新开局。

当前是规则与操作测试界面，并非一比一视觉成品。战斗由 Node 实时原规则执行，完整对局入口已显示实时位置、动画与血量：可用素材复用本地 Spine 模型，缺素材的单位显示带名称的占位块。地图使用原 stage 的 tileKey 绘制简化棋盘，尚非原版棋盘美术。原 `-play` 单场模型体验仍保留。已加入手牌/临时区/战场装备目标选择、满槽显式替换、法术地块施放、道具销毁、晋升奖励选择、已装备物品、盟约人数/等级/层数及策略效果文本。准备区可滚动；临时区未清空时禁用准备按钮。拖拽、原版 UI、完整素材与特效、准确相机/地形和联机尚未完成。

## 验证

`node tools/test-unity-match.mjs` 覆盖原协议拒绝非法购买、战前选择、购买扣费、手牌产生、查询不推进时钟、真实战斗结算到下一回合、引擎和调度器无错误。尚未声称全 UI 操作验证或稳定 60 FPS。

`node tools/test-unity-preparation.mjs` 使用受控物资状态验证原版装备、指定替换旧装备的销毁、三同名晋升与奖励领取、临时区阻止准备、释放手牌位后的自动补入。不是所有界面鼠标操作或法术效果的完整覆盖。

`node tools/test-unity-match-combat.mjs` 将完整对局适配器状态逐步与原 Battle.snapshot 比较，验证地图、单位元数据、事件和下一回合。`tools/measure-unity-match.ps1 -Combat` 运行原生可见单位与下一回合冒烟测试；画面仍有素材占位，不代表完整美术验证。
