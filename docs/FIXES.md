# 个人维护版问题修复记录

## 2026-10-10：骨骼刷新任务均摊（第三轮）

- 原因：随机刷新相位使同一刷新间隔内的每帧骨骼任务数不均，形成 CPU 和缓存绘制尖峰。分段采样中单位更新约 6–8 ms、共享缓存绘制约 2–3 ms；CPU 采样热点是 Spine 姿态计算。
- 改动：共享缓存顺序分配刷新相位；保留每个单位的动作时间累计、原有刷新间隔和动画混合。新增仅在开发场景 `measure=1` 启用的棋盘、状态、单位、特效、缓存分段耗时。
- 调度验证：120 个稳定单位、6 帧刷新间隔，每帧分配 20 次刷新；2–6 帧间隔均验证每周期每单位恰好一次，帧间数量差不超过 1。新动作、缩放与初次加载仍可追加即时刷新，不宣称实际绘制数始终等于 20。
- 回归：438 项渲染及战斗客户端测试通过、1 项跳过、0 失败；`git diff --check` 通过。
- 浏览器对比：同机 Edge 无界面、1920×1080、DPR1、高画质、120 单位、59 个真实骨骼模型和3D棋盘，预热30秒，各采集两个600帧窗口。旧版平均41.4/37.6 FPS，p95 30.4/42.3ms；新版平均37.8/48.3 FPS，p95 48.5/30.4ms。两个版本都无页面错误。窗口波动很大，不能证明稳定整体帧率提升，也未达到稳定60FPS。此环境与前两轮内置浏览器不同，不能直接横向比较。
- 部署状态：代码完成并准备发布；尚未更新 ECS。当前线上仍为第二轮构建 `6ac0557b0758`。本轮未能接入原有 Workbench 终端，保留线上正常运行版本。

## 2026-10-09：上游 Issue #428，蕾缪安通缉目标不能触发三技能

- 来源：[上游 #428](https://github.com/sganggs/Stronghold-Protocol/issues/428)。
- 基线：0.2.1，提交 `c2a2ef778cf728ff29b953b9842b2a39b1e9cbea`；本修复在 `personal-0.2.1` 分支维护。
- 复现：蕾缪安技力充满，精英敌人位于其他拉特兰干员范围内、自身原始范围外，达到通缉条件后仍无法通过该目标自动启动三技能。
- 原因：天赋通过 `setExtraRange` 扩展攻击范围，DEFAULT 技能触发检查使用 `baseRangeKeys`，未包含通缉目标所在格。
- 改动：天赋安装时使用现有 `SkillRuntime.addTriggerRange` 注册动态额外范围，沿用单位目标筛选 profile。
- 回归测试：范围外通缉目标触发技能及弹药锁定；已开启技能在敌人睡眠期间保留弹药、苏醒后恢复锁定；联防中由另一玩家的拉特兰范围触发通缉与跨场地锁定。
- 验证：`kits_t6`、`kits_alt_t6`、`feedback5-lemuen-s3-wait`、`combat`、`docs-consistency` 共 163 项测试通过，`git diff --check` 通过。
- 限制：报告版本为 0.2.2，本地尚未复现“已开启技能在敌人苏醒后仍不索敌”。本记录仅宣告已证实的自动触发缺口修复。
- 部署状态：2026-10-09 已部署阿里云运行实例，构建号 `441059a7f779`；与渲染优化一起更新。

## 2026-10-09：渲染开销优化（60 FPS 目标，第一轮）

- 基线：personal-0.2.1；保留现有战斗逻辑与素材。
- 改动：持续低帧时随既有负载等级降低 PIXI 与 3D 棋盘像素密度，恢复后逐级回升；静态后备装置缓存几何，位置、镜头或死亡动画变化时重绘；开发演示增加 600 帧平均 FPS 与 p95 帧耗时。
- 开销验证：DPR 2 最大降档每个主画布像素减少 64%；DPR 1 最低 0.75，像素减少 43.75%；静态装置 120 帧仅重绘一次。降档会使画面略软。
- 回归：node --test test/render/*.test.js test/sim/perf.test.js test/client/battle*.test.js：439 通过、1 跳过、0 失败。
- 浏览器验证：本机内置浏览器，1920×1080、DPR 1、高画质、120 单位、59 个 Spine 模型及 3D 棋盘。旧版窗口平均 36.5 FPS / p95 42.5 ms（另一窗口 44.2 FPS）；优化版降至 0.75 分辨率，完整 600 帧窗口平均 36.0 FPS / p95 36.3 ms。压力场景尚未达到 60 FPS，不能承诺所有设备稳定 60；帧率波动与 CPU/动画开销仍需后续分析。
- 部署状态：2026-10-09 已与 #428 修复一起部署，代码提交 `c6f70e12`、构建号 `441059a7f779`；下载文件 SHA256 全部通过、远端 JavaScript 语法检查通过。更新前在线连接与对局均为 0，更新后 /healthz 正常、游戏首页已连接、浏览器启动无错误。旧文件已备份，可恢复对应文件并重启服务。

## 2026-10-09：骨骼缓存容器迁移优化（第二轮）

- 发现：每次共享骨骼缓存刷新，都将模型移入绘制页、刷新后移回停放容器；持续重复数组查找、移动及父节点变更。
- 改动：刷新后隐藏模型并保留其绘制页，下一次刷新复用父节点；仅处理本帧排队的模型与擦除矩形。模型切换页和退出缓存仍使用原有迁移机制。
- 验证：437 项渲染和战斗客户端测试通过、1 项跳过、0 失败；新增刷新无需重复加入父节点以及刷新后模型/擦除矩形隐藏断言。
- 浏览器：1080p、DPR1、120 单位、59 个真实骨骼模型；旧版平均35.9 FPS，p95 36.4ms；新版预热后平均37.2 FPS，p95 36.4ms。早期窗口仅30.6 FPS，波动明显，此对比不能证明稳定帧率提升。模型缓存120槽、无容量溢出；浏览器无渲染错误。
- 本轮只确认减少重复容器操作，仍未达到压力场景60 FPS。开发场景新增 CPU/主绘制/缓存容量指标供后续定位。
- 部署状态：已部署代码提交 `aa0b175d`，新构建号 `6ac0557b0758`。更新前在线连接和对局均为0；文件SHA256及远端语法检查通过，旧文件已备份。更新后健康检查正常、首页已连接、浏览器无启动错误。
